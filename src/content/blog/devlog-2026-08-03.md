## TL;DR

- **Sonar went from static mock to merged app in one sitting.** A pixel-perfect React SPA plus a FastAPI backend-for-frontend, built as a Databricks Asset Bundle with the built frontend committed straight into `src/static/` so deploy needs no Node toolchain.
- **27 tests, one fidelity rule that actually mattered:** Tailwind's preflight resets `line-height` to 1.5, and the design prototype assumes the browser default — leaving that in place quietly drifts every line box in the UI.
- **The deploy target had to move again.** The workspace this was built against turned out to be billing-restricted and refuses new app creation outright. Second PR of the day just re-points the bundle at a fresh Free Edition workspace.

## What Sonar is

Sonar is a chat-first analytics app for call-center intelligence — the kind of thing a QA director opens to ask "what were the primary call drivers last week," then narrows to "which categories had low sentiment," then "which agents," then pulls the actual call transcripts. It's the front end for a pipeline I've written about before: recordings transcribed and LLM-labeled into a gold table (`calls_labeled` — drivers, sentiment score, escalation flags, QA rubric checks), the same lakehouse shape as the [dual-index RAG work](/blog/call-intelligence-lakehouse).

The design arrived as a single static HTML file with inline styles — a working prototype, not code to copy, but pixel-final on colors, spacing, and motion. Three panes: conversation history on the left, a chat column in the middle with streaming-simulated responses and typed block types (text, bar charts, tables, agent cards, call chips), a tabbed report/charts/transcripts/data panel on the right. Dark by default, monochrome accent, IBM Plex everywhere.

## Building it in one pass

The whole thing landed as three commits and merged same-day: a FastAPI BFF first, then the SPA, then the bundle plus CI plumbing.

The backend is honest about what's real. `sonar.gold.calls_labeled` doesn't exist yet in the dev workspace, so the data layer probes Delta once at startup and falls back to canned fixtures that mirror the design's seed data exactly — surfaced plainly in `/api/health` as `"provider": "canned"` rather than pretending. Chat itself is a deterministic keyword router today, emitting the same block schema (`isText` / `isBars` / `isTable` / `isAgents` / `isChips`) that a real model will need to emit later, so swapping the router for an actual serving endpoint is additive, not a rewrite.

The frontend chase for pixel fidelity turned up one gotcha worth remembering: Tailwind's preflight sets `line-height: 1.5` globally, and the prototype was built against the browser's default line box. Left alone, that one reset line silently drifts every message, label, and card vertically out of alignment with the reference screenshots. Resetting it back to `normal` in the global stylesheet was the fix, and it's now called out explicitly in the repo's `AGENTS.md` so it doesn't get "cleaned up" by a future pass. Built output gets committed straight into `src/static/`, so a deploy never needs a Node toolchain — the bundle just ships static files and a Python backend.

CI is the same GitHub → Azure DevOps mirror trunk from earlier projects: a workflow mirrors branches to ADO, a validate pipeline backs the PR policy, a deploy pipeline runs on merge to `dev`. All of it committed inert, pending one-time secret and pipeline registration — plumbing before power, same as always.

## The wall, again

The second PR of the day was smaller and more familiar than I'd like: the workspace this was built and validated against turned out to be billing-restricted, and its resource gatekeeper denies new app creation outright — `DENY_NEW_AND_EXISTING_RESOURCES / ABUSE` — on the final `apps create` step. Not a bug to fix, a dead end to route around.

This is the same shape of problem as [the free workspace that got cancelled outright a couple weeks back](/blog/devlog-2026-07-20) — a Free Edition environment turning out to be a worse foundation than it looked, mid-project. The fix is the same too, because the lesson from last time actually held: everything here is config, not hardcoded state. The PR swaps `databricks.yml`'s targets, the app's warehouse binding, and the doc references over to a second Free Edition workspace, revalidates the bundle against the new host, and leaves a do-not-deploy note on the old one. Nothing about the app itself changed — Sonar didn't know or care which workspace it was pointed at, which is the entire reason bundle-first discipline keeps paying for itself.

## What's next

Chat is still a keyword router, and the plan for turning it into a real model is already written down: wire it to a Databricks serving endpoint (`databricks-llama-4-maverick` — the Claude endpoints are rate-limited to zero on this Free Edition tier) with tool-calling over the same data-provider methods the canned router already uses, and swap the client-side streaming simulation for real token streaming. That's earmarked as its own PR rather than folded into v1, which is the right call for something this easy to get wrong under review.
